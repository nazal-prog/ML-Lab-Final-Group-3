# MailGuard --- Power BI Dashboard & Business Intelligence Analytics

## Project Overview

**MailGuard** is an end-to-end machine learning solution for classifying
incoming SMS/email-style messages as **Spam** or **Ham**. The project
follows an enterprise machine-learning workflow covering data
preparation, exploratory analysis, model development, evaluation, error
analysis, analytics engineering, and interactive business intelligence.

The Power BI layer converts machine-learning outputs into an
executive-friendly dashboard for understanding model performance,
prediction outcomes, risk levels, classification errors, and threshold
behavior.

------------------------------------------------------------------------

## BI Developer Role

### Power BI Dashboard & Business Intelligence Analytics

The BI developer is responsible for integrating machine-learning and
analytics-engineering outputs into an interactive Power BI dashboard.

Key responsibilities include:

-   Integrating model evaluation and prediction outputs into Power BI.
-   Creating executive KPI summary cards.
-   Comparing candidate ML models using Precision, Recall, F1-score, and
    PR-AUC.
-   Visualizing prediction outcomes and classification errors.
-   Providing interactive risk-level filtering.
-   Presenting sample message predictions and spam probabilities.
-   Visualizing threshold trade-offs between Precision, Recall, and
    F1-score.
-   Designing a clean, executive-ready multi-page dashboard.
-   Preparing BI documentation and dashboard artifacts for
    reproducibility.

# Dashboard Pages

## 1. Executive Overview

The Executive Overview provides a high-level view of operational and
model performance.

### KPI Cards

The dashboard includes:

-   **Test Messages**
-   **Spam Precision**
-   **Spam Recall**
-   **Spam F1**
-   **Spam PR-AUC**

### Prediction Outcomes

The dashboard visualizes the prediction outcome categories:

-   True Negative
-   True Positive
-   False Negative
-   False Positive

### Risk-Level Slicer

An interactive `risk_level` slicer allows users to filter prediction
outcomes by:

-   Low
-   Medium
-   High

### Sample Message Predictions

The dashboard also displays sample predictions containing:

-   Message
-   Prediction
-   Spam Probability

This provides a concrete view of individual model outputs.

------------------------------------------------------------------------

## 2. Model Comparison

This page compares the candidate machine-learning models using
cross-validation results.

### Visuals

-   **F1 Score by Model**
-   **Precision, Recall & F1 by Model**
-   **PR-AUC by Model**

### Candidate Models

-   Logistic Regression
-   Multinomial Naive Bayes
-   Linear SVM

The comparison uses cross-validation metrics generated by the Data
Science workflow.

------------------------------------------------------------------------

## 3. Threshold Analysis

This page examines how changing the spam-classification threshold
affects model behavior.

### Visual

**Threshold vs Precision, Recall & F1**

The analysis uses threshold values from 0.10 to 0.90 and displays the
corresponding:

-   Precision
-   Recall
-   F1-score

### Purpose

Threshold analysis helps demonstrate the trade-off between:

-   Reducing false positives
-   Capturing more spam messages
-   Maintaining a balanced F1-score

The threshold analysis supports operational interpretation of the spam
classification decision rule.

# Key Model Results

The final selected model was evaluated on a held-out test set.

  Metric             Result
  ---------------- --------
  Accuracy           98.16%
  Spam Precision     95.90%
  Spam Recall        89.31%
  Spam F1            92.49%
  Spam PR-AUC        97.08%

The final evaluation contained **1,034 test messages**.

### Confusion-Matrix Results

  Outcome             Count
  ----------------- -------
  True Negatives        898
  False Positives         5
  False Negatives        14
  True Positives        117

For the MailGuard use case, false positives are particularly important
because incorrectly classifying legitimate messages as spam can result
in important messages being missed.

# Dashboard Design Principles

The dashboard was designed around the following principles:

-   **Executive readability:** Key metrics are visible at the top level.
-   **Model transparency:** Candidate models can be compared across
    multiple metrics.
-   **Error visibility:** False positives and false negatives are
    explicitly displayed.
-   **Interactivity:** Risk-level filtering allows users to explore
    subsets of predictions.
-   **Operational analysis:** Threshold analysis shows how the decision
    threshold changes Precision, Recall, and F1.
-   **Traceability:** Dashboard visuals are based on project-generated
    ML and analytics-engineering outputs.
-   **Consistency:** Metric names, titles, and page structures are kept
    consistent across the report.

# How to Use the Power BI Dashboard

1.  Open `MailGuard_PowerBI_Dashboard.pbix` using Power BI Desktop.
2.  Review the **Executive Overview** page for high-level KPIs and
    prediction outcomes.
3.  Use the **Risk Level** slicer to filter prediction outcomes.
4.  Navigate to **Model Comparison** to compare candidate ML models.
5.  Navigate to **Threshold Analysis** to examine Precision, Recall, and
    F1 across different thresholds.
6.  Review the **Sample Message Predictions** section to inspect example
    model outputs.

# Reproducibility

The Power BI dashboard depends on the project-generated output datasets
listed above.

When moving the project to another machine:

1.  Keep the Power BI file and source output files available.
2.  If Power BI reports missing file paths, update the data-source paths
    in Power BI Desktop.
3.  Refresh the dataset after correcting the paths.
4.  Verify that all visuals and filters update correctly.
5.  Save the refreshed `.pbix` file.

# Viva / Presentation Talking Points

### What did you do as the BI developer?

> I integrated the machine-learning and analytics-engineering outputs
> into an interactive Power BI dashboard. I created executive KPI cards,
> model comparison visuals, prediction outcome analysis, risk-level
> filtering, sample prediction views, and threshold analysis to connect
> model performance with operational interpretation.

### Why did you include Precision, Recall, F1 and PR-AUC?

> These metrics provide a more complete evaluation of a spam classifier
> than accuracy alone. Precision is especially important because false
> positives can cause legitimate messages to be classified as spam.

### Why did you include a risk-level slicer?

> The slicer allows users to interactively examine prediction outcomes
> for different levels of spam probability risk.

### Why is threshold analysis useful?

> The classification threshold controls how the model converts spam
> probability into a final spam or ham decision. Changing the threshold
> affects Precision, Recall, F1, and the number of false positives and
> false negatives.

### What is a false positive in this project?

> A false positive occurs when a legitimate Ham message is incorrectly
> classified as Spam.

### What is a false negative?

> A false negative occurs when a Spam message is incorrectly classified
> as Ham.

# Limitations

-   The Power BI dashboard is based on the available project output
    datasets and does not itself retrain the machine-learning model.
-   The sample prediction table contains example inference records
    rather than a live user-input prediction service.
-   Threshold analysis is based on the generated test/evaluation output.
-   The Power BI report requires Power BI Desktop and access to its
    underlying data sources for full refresh functionality.
